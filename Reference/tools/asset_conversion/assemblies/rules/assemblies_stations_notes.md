# Station assemblies: sources and uncertainties

Output: `assemblies_stations.json` (121 entries, generated by `st_gen.py`). The file has 88 standard index-formula stations, 23 special assemblies and 10 `origin: "unreferenced"` models.

## PlayerStation composition rule (in order of evaluation)

1. `pv = loadStationCollision(index)`. If index ∉ {109, 110} and pv == NULL (no collision.json entry):
   - `inAlienOrbit && dlc1Won`: battlestation. Root 16928 plus 16929 and 16930 as bare transforms. Collision 1003.
   - `inAlienOrbit && !dlc1Won`: void station. Root 16443 plus 16446 and 16449. Collision 1001.
   - Otherwise: Vossk station. Root 16436 plus 16439 and 16442. Collision 1000.

   This covers every Vossk-race station, since none of them has a collision entry.
2. Default root: `index ∈ 109..111 ? 21076 (station_076_midorian) : 21000 + index`. The race comes from `SolarSystem::getRace`, or 9 if there is no system.
3. Special cases by index:
   - **111**: if mission ≤ 93, root 21076 plus 21876, 22076, 18781 and 18782 (burning overlay). If mission > 94, the wrecked station. If mission is exactly 94, it falls through to the race-3 rule with nonexistent children 21911 and 22111.
   - **101**: battlestation. In mission 157, if the current station is 112, the plasma gun (18768, 18770, 18769) is added.
   - **109 / 110**: wrecked station. Root 18771 plus 18772, 18773 and 18774. Static collision 2002. The last two ids don't exist anywhere.
   - **100**: deep science. There are three variants (normal with LOD 16934 at 70000; damaged; explosion in mission 80), described in the JSON.
4. Race 0 or 2 (Terran, Nivelian): children are `21800 + i` (emissive), then `22000 + i` (lights). Race 3 (Midorian) gets the same children. Index 108 additionally gets 22900 to 22903 (Kaamo fx, each animated every frame). Any other race gets the root only.
5. The root always gets `setRotation(0, π, 0)` and there is no scaling. Regular stations have no LODs and no `setLodLastVisibleDistance`.

Other behaviour:
- All children sit at identity. They are separate AEGeometry objects or TransformCreate+AddMesh transforms, added with `addChild`.
- `PlayerStation::update` advances the animation of the **last added child** (the lights/_add mesh) every frame, except for index 101 or in alien orbit. It also animates the emitters for index 100 and the 4 fx children for index 108.
- `addChild` keeps the last child at +0x14 and the one before it at +0x10. `setLodMeshes` also parents the +0x14 child under every LOD transform, so for deep science the `_add` mesh stays visible at LOD 1.
- **LOD switching**: distances are stored squared. LOD i is used when `dist² > f·dᵢ²`, where f is 1.0, 0.75 or 0.5 depending on the quality parameter (thresholds 0.66 / 0.33).

## When a station exists at all
`Level::createSpace` builds no PlayerStation in an empty orbit, unless it is also an alien orbit or the index is 27, 110 or 111. Empty orbits are:
- 102, 103, 104, 109, 132, 133, 134
- 111 after mission 93
- 101 after mission 0x54
- a few campaign states

So Terran 102-104 and 132-134, which have no collision entry, never fall into the Vossk branch.

## Positions
- The only fixed offsets found are:
  - turret gun at (0, 565, -528);
  - the mission-80 battlestation turret/shield table (12 entries, in the JSON);
  - mission-89 Luur objects at (-77000, -3000, 90000).
- All of these are engine-space game units, the same frame as the .aem vertices. `aem2fbx.py` treats .aem data as engine space (GL, Y-up).
- The table positions match the battlestation's emissive part centres: turret 9 is at (29716, 4854, -3758), emissive part2 is at (29691, 4579, -3426).
- For Unity, apply the project rule to these offsets as to any engine position.

## Data files
- **`stationparts.json`**: loaded only by `FileRead::loadStationParts`, which has **no callers**. It is dead data and not used for assembly.
- **`docks.json` / `docks_hd.json`**: the `station` field is **not** a station index. It is the space-point set passed to `loadSpacePoints(n)`:
  - 1: mining plant
  - 2: container_003
  - 3: sn cargo wreck
  - 4: cargo_001_midorian
  - 6: burning station
  - 7: battlestation
  - 10: sn_113 proxy
  - DAT_002537a4: per-type table in createMission

  PlayerStation itself uses no dock points.
- **`collision.json`**: ids 0-123 are station indices (by index); 1000 is Vossk, 1001 void, 1002 pirates, 1003 battlestation, 1005 deep science damaged/explosion. 2000+ ids are in static_collisions.json.

## Uncertainties
- **Animation state semantics**: I didn't decode what `SetAnimationState(state, x)` does. Values 0, 1 and 2 are used, and `Transform::Update(t, t+0xf8)` at construction probably jumps to a fixed frame.
- **Duplicated meshes**: the duplicate 18781 child in the burning station static object and the doubled shield mesh are what the code does. They are probably harmless bugs.
- **Missing float arguments**: some mission-specific `setRotation` calls lost their float arguments (cases 0x59 and 0x9a).
- **Static objects vs station ids**: the pirate, mining plant, burning station and battlestation static objects are PlayerFixedObject assemblies, not PlayerStation, and their placement comes from waypoints and mission code.
- **sn_station_113 proxy**: when the col_box proxy (case 0x66) actually shows its sn_station_113 wreck mesh depends on PlayerFixedObject state (3/4), which isn't fully traced. `KIPlayer::setActive`'s bool argument was lost.
