# In-space level objects: assembly notes

Output: `assemblies_level.json` (63 entries), generated by `lvl_build.py`. All positions are in GAME units, before the `(x,y,-z)*0.05` conversion.
Helper files: `armdis.py` (Thumb disassembler with literal-pool floats, needs `pip install capstone`), `lvl_idrefs.py`/`lvl_idrefs.txt` (every relevant mesh id and the functions that reference it), `lvl_findval.py`.

## Engine rules (AbyssEngine AEGeometry, 0xb0d20..0xb1a86)
- `AEGeometry(meshId)` creates a transform with the mesh. `addChild(t)` attaches transform t to the current root (`+0xc`) and remembers the last two children (`+0x10`, `+0x14`).
- `setLodMeshes(ids, dists, n)`: one extra transform per LOD. Distances are stored **squared**. If a child was already added, only the **last** child (`+0x14`) is attached to every LOD transform.
- `updateLod(camPos, quality)`: LOD k is picked when `dist^2 > q * lodDist[k]^2`, with q = 1.0 (quality > 0.66), 0.75 (> 0.33) or 0.5. The rendered root (`+0xc`) is swapped to the LOD transform, so the other base children are no longer drawn.
- `setLodChildMeshes(ids)`: adds one extra mesh per LOD and re-adds the last child after it. `setLodChildTransform(t)`: attaches transform t to every LOD.
- `setLodLastVisibleDistance(d)`: stores d^2. The object is hidden when `dist^2 > d^2`. **None of the in-space objects in this area call it.**
- Transform field `+0xe0` (set to 20000 for explosions, 500000 for wrecks, 1e6 for turret pivots, 10000 for fire streaks) is most likely a culling/bounding radius.
- `PlayerStaticFar::update` (jumpgates, wormhole): beyond 295001 units from the camera, the object is drawn at 295000 along the view ray and scaled by 295000/dist.

## Uncertainties
- **v_autoturret_003 gun offset** decodes as (34, 88, 1.6). The x=34 looks odd. The other turrets have x=0.
- **Rotation mapping:** AEGeometry::rotate(0,π,0) is assumed to be a 180° yaw (softfp args r1,r2,r3 = x,y,z).
- **Fighter-mounted turret hosts:** KIPlayer+0x78 == 0x2d / 0x33 is probably a ship index (45 Bloodstar, 51 Rhino). Not verified.
- **Pirate station and battlestation children** are added at identity. The layers are assumed to be pre-positioned in the mesh files; none of their children has an explicit offset.
- **Battlestation shield (0x381d)** is a PlayerTurret whose root and pivot-base are both mesh 14365. The same mesh is drawn twice, so treat it as a single mesh.
- **Asteroid LOD sets:** the JSON `lods` use the phone "near" set. The far and iPad sets are in `related.lodSets`. The asteroid rotation around y was lost in the decompile.
- **Suns and planets** are camera-facing billboards rebuilt every frame (StarSystem::render). The JSON gives their scales and texture tables, not a static hierarchy.
- **Gas clouds:** the KIPlayer geometry is mesh 14289 (`bra.fbx`), apparently a dummy. The visible cloud is a separate billboard.
- **Carrier 0x498e (Models/meshes/carrier.fbx):** Level::createMission calls createStaticObject(0x498e), but no branch handles it (it would dereference a null object), so this looks like dead or dev code. It is not in the JSON.
- **Resource-id oddities:**
  - Id 19080 is registered twice: the mining plant, and later `test_dock.aem`. `gof2bin.mesh_name(19080)` returns `test_dock`.
  - Ids 11761/11762 (sn_sun_explosion_ring/core) exist as FBX but are missing from `resources.json meshes[]`, because the table registers them as type 2.
